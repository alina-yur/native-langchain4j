= Native LangChain4j Example

This demo is a small GraalVM Native Image command-line assistant built with LangChain4j 1.19.0. It demonstrates the Agentic API, streamed responses, per-session chat memory, strict tool calling, and a read-only local runtime-information tool.

== Prerequisites

* GraalVM for JDK 25, including `native-image`
* Maven 3.9+
* An OpenAI API key for live requests

The model defaults to `gpt-5.6-terra`. Set `OPENAI_MODEL` to use another compatible model. `OPENAI_BASE_URL` can point to an OpenAI-compatible endpoint, and `OPENAI_REASONING_EFFORT` can override the default `none` setting.

== Build and run on the JVM

[source,shell]
----
mvn package
export OPENAI_API_KEY=your-key
./run-jvm.sh "What is GraalVM Native Image?"
----

With no prompt, the application starts an interactive session:

[source,shell]
----
./run-jvm.sh
You> What runtime am I using?
You> /reset
You> /exit
----

The assistant uses the `system_info` tool for local runtime questions. The tool exposes only runtime, operating-system, architecture, and processor-count information.

== Build and run as a native executable

[source,shell]
----
./build-native.sh
./target/native-langchain4j "Explain ahead-of-time compilation in one paragraph"
----

The build uses the GraalVM Native Build Tools Maven plugin and the application’s minimal reachability metadata. It does not rely on a fallback image or deprecated builder-class options.

To validate the native executable without an API key, run the offline mock SSE/tool-call test after compiling the test classes:

[source,shell]
----
mvn test
./native-smoke.sh
----

== Configuration

`OPENAI_API_KEY` is required for live requests. The optional variables are:

* `OPENAI_MODEL` — model name; defaults to `gpt-5.6-terra`.
* `OPENAI_BASE_URL` — endpoint override for compatible services or local tests.
* `OPENAI_REASONING_EFFORT` — reasoning setting; GPT-5.6 tool calls use `none` by default with Chat Completions.

The Agentic module is experimental in LangChain4j and may change in future releases. The demo intentionally keeps the agent single-process and single-agent so its native-image behavior remains easy to inspect.
